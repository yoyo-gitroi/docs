## Top hazards for a browser agent

| Hazard | Where | What the playbook does |
|---|---|---|
| **Send reply** has no confirm, only a 5-second undo, and leaving the page during that window sends at once | [Email and replies](/operations/email-and-replies) | Approval stop before **Send**; stay on the page for the undo window |
| **Send & create case** on a new email sends immediately with no undo; Enter in To, Cc or Subject submits the form | [Email and replies](/operations/email-and-replies) | Approval stop; never press Enter in those fields |
| Single keys in the Operations inbox (`e`, `1`, `2`, `3` and others) act instantly with no dialog; row quick actions only show on hover | [Inbox](/operations/inbox) | Never press single-letter keys outside a text field |
| The request typed on Documents is held in page memory; reloading before the chat opens loses it, and **Blockers** cards vanish on reload | [Create a document](/documents/create-a-document) | Do not reload; answer in the message box if the card is gone |
| **Generate now**, `/generate` and packet runs create template-default documents with no AI writing; `/generate` silently picks the first client when the URL has none | [Generate page](/documents/generate-page) | Always pass `client=`; fill fields after generating |
| Client links without `?tab=` reopen that user's last-used tab | [Client profile](/clients/client-profile) | Always open `/clients/{slug}?tab=…` |
| Operators see some enabled controls that the server refuses with 403 (HR Advisor select, Profile Workspace **Save**, compliance **Run research**, External Documents) | [Clients](/clients/clients-list) | Expect the 403; do not retry; switch account only if allowed |
| The contacts API route is not mounted, so `/contacts`, `/contacts/{id}` and CRM Hygiene likely fail behind "No contacts yet." | [People and contacts](/clients/people-and-contacts) | Use the client's People tab instead |
| Several irreversible actions have no confirm: memory delete, road map task trash, jurisdiction ×, question ×, campaign **Cancel**, template **Archive**, roadmap **Approve** and **Mark lost**, integration **Disconnect**, Tracker Status "Cancelled" | Many pages | Approval stop before each one |
| **Sync HubSpot** fails for Operator and Admin, so **New implementation** never unlocks for them | [Implementation portfolio](/implementation/portfolio) | Use `/implementation/new` instead |
| Some settings pages have no route guard, so an Operator can edit compliance rules and roadmap blueprints by URL | [Catalogs and defaults](/settings/catalogs-and-defaults) | Do settings work as the Principal only |
| Meeting preps and some research results never refresh by themselves; roadmap drafts are lost unless **Accept draft** is clicked | [Sales](/sales/today-and-accounts) | Click **Refresh** or **Check for result**; accept drafts before leaving |
| The Sales sidebar is icon-only below 1536 px wide | [Sales](/sales/today-and-accounts) | Find items by `title` or link target, or use a wider window |
| Some icon buttons have no accessible name (Team Deactivate and Activate, Drive config save icons, compliance Active toggle, roadmap trash icons, People-tab icons) | Several pages | Recipes give a visual cue for each |
| "Invitation sent" does not prove delivery; email failures are only logged on the server | [General and team](/settings/general-and-team) | Report it as "invite queued", not "delivered" |

## All findings by area

Each bullet names the playbook page it affects. Source references point into the Ariya repo.


### Documents

- `/documents/create-a-document`: the opening request is handed from the landing to the chat page in memory only (`pending-ask.ts`). A reload or hard navigation between **Send** and the chat page loses it, leaving an empty chat.
- `/documents/create-a-document`: Blockers cards with choice questions offer no free-text option; when no choice fits, the only route is to ignore the card and answer in the composer.
- `/documents/create-a-document`: Blockers cards are not restored after reload or reopening a chat (only user/assistant messages are reloaded), so pending questions silently disappear.
- `/documents/create-a-document`: the document assistant refuses the three official PDF forms (`generate_draft` accepts only `db` render-source templates), but nothing in the chat UI says so up front. UNVERIFIED in a live run.
- `/documents/create-a-document`: there is no refusal UI; refusals arrive as prose, the generic banner "The assistant could not finish this request.", or a status line.
- `/documents/documents-home`: `?source=operations` (Operations **Deliverables** link) is ignored by the page.
- `/documents/documents-home`: `?client={slug}` with a slug not in the list leaves the picker reading "Select a client…" while the binding is still applied; **Send** then fails with a server error.
- `/documents/documents-home`: the landing client picker (and the template drawer picker) cannot be cleared; only a reload resets it.
- `/documents/documents-home`: document search matches the client slug, not the client display name.
- `/documents/documents-home`: the card delete bin is opacity 0 until hover.
- `/documents/documents-home`: StarterChips ("Incident report", "Offer letter", …) exist in code but are not rendered.
- `/documents/documents-home`: `/documents/assistant` redirect keeps only `client` and `case`; `view=chats` and anything else is dropped.
- `/documents/documents-home`: help guide `documents-list` says the drawer may show "Preview failed"; code text is `Preview failed ({status})`.
- `/documents/chat-workspace`: the client cannot be changed inside a chat; **Switch client (new chat)** / **Choose client** just navigate to `/documents` and open no picker.
- `/documents/chat-workspace`: rail **Delete chat** deletes immediately with no confirmation and is hover-only.
- `/documents/chat-workspace`: the doc agent auto-approves its own tool approvals and can write to the client profile (`update_client_profile`) without user confirmation.
- `/documents/chat-workspace`: help guide mentions "An attached image is too large (max ~4.5MB)"; the web code allows images up to 20MB and has no such message (server text UNVERIFIED).
- `/documents/chat-workspace`: a second tab sending to the same chat gets "Your last message was not sent because the assistant was still busy. Send it again."
- `/documents/chat-workspace`: the preview iframe is `sandbox=""` srcDoc; DOM-based agents may not be able to read the draft text.
- `/documents/document-editor`: Google Docs export ("Open in Google Docs" / "Google Docs") is commented out in the editor, chat preview and library drawer while the API endpoint still exists; no UI path exports to Google Docs.
- `/documents/document-editor`: **E-signature delivery** is permanently disabled ("Coming soon; no external send path").
- `/documents/document-editor`: **Complete Document**, **Enrich with AI** and **Polish** still render for DB-only/legacy documents but their endpoints return HTTP 410 ("Endpoint removed — …").
- `/documents/document-editor`: plain-text documents say "Regenerate it to make changes." but no Regenerate button exists anywhere.
- `/documents/document-editor`: PDF-form values are saved only by **Save fields**; autosave, toolbar **Save** and downloads do not save them and there is no unsaved-changes warning.
- `/documents/document-editor`: **Approve & Deliver** closes the linked request with no undo in the editor; toast says "delivered locally".
- `/documents/document-editor`: help guide names the chat icon "Edit this document in chat"; when a source chat exists it is "Open the chat this document came from".
- `/documents/document-editor`: the toolbar scrolls horizontally on narrow screens, which can push **Share** and **Save** off-screen.
- `/documents/templates`: several templates share a title (for example "HR Incident Report" for `hr-incident-report` and `incident-report`), and the slug is shown only on the studio page, not on cards or in the drawer.
- `/documents/templates`: **Use in chat** passes only prose (`Draft a {title} for {client}: `), not a template id, so the assistant may pick a different template; the pre-fill is lost on reload.
- `/documents/templates`: there is no Publish button; the view-only capability label still reads "Templates: upload, edit, version, publish". Locking a version is the only publish equivalent.
- `/documents/templates`: help guide `documents-templates` quotes "You need admin access to change templates — ask an owner or admin to make this change."; code says "Your profile cannot change templates — ask a Principal or Admin to make this change."
- `/documents/templates`: help guide says the wizard button is **Save Template**; code button is `Save v{n} as template`.
- `/documents/templates`: wizard drafts are page-memory only and lost on reload or navigation.
- `/documents/templates`: Settings mirrors (`/settings/templates*`, `/settings/brand-assets`, `/settings/packets`) are hidden from non-Principal/Admin navigation, but no client-side route guard was found (UNVERIFIED).
- `/documents/templates`: `/settings/templates` uses a different list component from the gallery (no drawer, no **Use in chat**, no **Generate now**).
- `/documents/brand-and-packets`: brand **Create a copy** on a platform set does not copy it; it opens a blank set with default values.
- `/documents/brand-and-packets`: brand sets do not affect existing documents or the letterhead of new ones (that comes from Settings → General); the page itself says wiring is pending.
- `/documents/brand-and-packets`: brand set **Delete** and packet delete both act immediately with no confirmation.
- `/documents/brand-and-packets`: the brand-card eye (preview) button has no aria-label or title.
- `/documents/brand-and-packets`: packet run results are not persisted; navigating away (including clicking **Open** in the same tab) loses the list.
- `/documents/brand-and-packets`: help guide `documents-packets` lists only `/documents/packets`; `/settings/packets` is the same page.
- `/documents/generate-page`: `/generate` is hidden from Documents navigation but is still the target of client **Generate Document**, Roadmap **Draft**, **Draft with context**, Requests, Sales **Generate assessment**, HR Intel and case **Generate from case** (assistant off).
- `/documents/generate-page`: with no `client=` the page auto-selects the first client returned by the API, and **Generate** for a non-client-scoped template falls back to `clients[0]` silently, risking a document for the wrong client.
- `/documents/generate-page`: `request_id`, `source=hr-roadmap`, `source=request` and `source=hr-assessment` are passed by callers but ignored.
- `/documents/generate-page`: only code-registry templates are listed; tenant/DB-only templates (customized or workspace-authored) are missing, and field labels can differ from the editor/gallery for the same template.
- `/documents/generate-page`: the **Research + fill** prompt tells the model to "preserve unknown facts as placeholders", which conflicts with the no-placeholder rule used by the document assistant.
- `/documents/generate-page`: "HR operator templates" and "All code templates" show the same list; per-section Polish controls are not rendered (props unused); `generate-layout.ts` is dead code.
- `/documents/generate-page`: `/template` (Templates DB-only POC) is reachable by direct URL with no role gating.
- `/documents/generate-page`: no in-app help guide exists for `/generate`.

### Templates and catalog

- `/documents/catalog/business#hr-incident-report-incident-report`: two active templates share the title "HR Incident Report" (`hr-incident-report` and the database-only `incident-report`). Title matching and catalog search depend on alphabetical order; an agent picking by visible title can land on either. The playbook heading for `incident-report` had to be disambiguated with its slug.
- `/documents/choosing-a-template#discipline-and-incidents`: client-workspace document opportunities and evidence hints still suggest `incident-report-rdk`, a retired client-specific (Riverboat Delta King) layout, while Operations case rules suggest `hr-incident-report`.
- `/documents/catalog/business#employee-handbook-assessment`: a repair script marks `employee-handbook-assessment` (and eight other database-only templates) as "GONE — deactivate", but migration 0100 re-seeded them as active. A title match on "handbook assessment" lands on this older row, not its successor `employee-handbook-discovery-assessment`. Live active state unverified.
- `/documents/catalog/business#non-disclosure-agreement`: the assistant's template word search does not rank `nda` in its top 5 for the word "NDA" (the token matches inside other words and ties sort alphabetically). Only "non-disclosure agreement" works reliably.
- `/documents/choosing-a-template`: platform templates have no aliases in any seed and no API edits aliases, so all routing is title or word overlap. Several common phrases route to the wrong template first: "onboarding" → `contractor-onboarding-packet-1099`; "HR roadmap" → module-generated `elevated-hr-roadmap`; "service agreement" → `client-service-agreement`; "termination letter" ties `personal-engagement-letter`; "quarterly business review" ties `performance-review`; "job offer" ties `job-description`.
- `/documents/catalog/pdf-forms`: the assistant refuses the three PDF forms with a message telling the user to "migrate this template to the database first", which is not possible (PDF forms are code-only by design). The message misleads users; it should point to Documents → Templates.
- `/documents/how-templates-work#generate-action-versus-the-assistant`: the Generate action on Documents → Templates (and `/generate`) does not call the LLM for Handlebars templates. Users who press Generate expecting written content get defaults plus client prefill only.
- `/documents/generate-page`: the `/generate` page builds its catalog and forms from the code backup registry (96 templates). It lacks the 13 database-only templates (all policy templates, `hr-assessment`, `incident-report`, `implementation-billing-memo`, the `elevated-*` templates) and the 3 PDF forms, and it lacks the team-member dropdowns migration 0120 added to 8 database forms. Field labels can therefore differ from Documents → Templates and the editor.
- `/documents/how-templates-work#client-scope-and-tenant-scope`: `/generate` silently falls back to the first client in the list when the chosen template has no client-prefill fields; an agent that skips the client picker creates a document for the wrong client.
- `/documents/how-templates-work#client-scope-and-tenant-scope`: the Document Assistant requires a bound client for every template, including tenant-internal pieces (flyers, business card, board update, cap table). There is no way to draft an internal document without attaching it to some client.
- `/documents/how-templates-work#fields-and-sections`: `protectedFields` ("fields the AI chat assistant must NOT modify") are declared on 28 templates, but no enforcing code was found in core, transport-api or web.
- `/documents/how-templates-work#template-versions-and-forks`: `internal-docs/18-document-agent-pipeline.md` describes template statuses (approved / system_generated / draft) that are not implemented anywhere; templates have no draft/publish state.
- `/documents/choosing-a-template#other-places-that-suggest-templates`: `shared/src/hr-document-types.ts` claims every HR Roadmap linked-doc value is a registered template slug, but 14 values (`pip`, `separation-agreement`, `handbook-addendum`, `policy`, `safety-manual`, `onboarding-checklist`, `offboarding-checklist`, `idp`, `training-plan`, `incident-report`, `verbal-warning`, `audit-guide`, `compliance-audit`, `hr-proposal`) are not registered code slugs; Draft falls back to the nearest template or `hr-roadmap`.
- `/documents/catalog/business#isolved-billing-memo`: migration 0140 updates sample data in `isolved-billing-memo`, which no migration or seed creates. Either a stale reference or a template that exists only in some live databases.
- `/documents/catalog/business#invoice`: a stale tenant `invoice` row shadowed the platform `invoice` on one environment (handoff doc, "Open — needs a decision"); resolution prefers tenant rows, so the stale form wins silently.
- `/documents/how-templates-work#brand-application`: Handlebars documents always render with the tenant brand kit; a client's own brand (`clients.config.brand`) is ignored except by the legacy renderer and the PDF footer. Product intent unverified.
- `/documents/how-templates-work#export-formats`: DOCX export is plain paragraphs only (HTML stripped to text, no tables or styling), so table-heavy templates (invoice, pricing quote, cap table, risk register) lose their structure in DOCX.
- `/documents/catalog/data`: template metadata advertises `xlsx` (and `png`) exports for data templates, but no xlsx export endpoint exists; the metadata is descriptive only.
- `/documents/catalog/sales`: the DB has category `sales` (7 platform rows plus tenant `billing-memo` as "Sales"), but the TS template category type lists only business, print, social, data and marketing.
- `/documents/catalog/business#status-report`: the Health dropdown options start with emoji (green, yellow and red circles), which screenshot-driven agents may misread; text locators should use "Green — on track" etc.
- `/documents/how-templates-work#blockers-and-follow-up-questions`: `POST /api/documents/:id/complete` returns 410 "Endpoint removed — use the Enrich draft button in the editor."; any UI or help text still pointing to a "complete" action is dead.
- `/documents/how-templates-work#packets`: no packets are seeded; the Packets tab is empty on a fresh install. Packet create/edit/delete is role-gated (Principal, Admin), but packet generate has no role check.
- `/documents/how-templates-work#client-scope-and-tenant-scope`: Slack refuses every `client`-scope template ("not yet on the agentic document-builder path"), so the policy templates, employee handbook, pay increase notice and HR Roadmap documents cannot be created from Slack.
- `/documents/catalog/pdf-forms`: creating a PDF form from the Documents UI is code-verified only, not checked in a live run.
- Not a template issue, found while compiling: `documents/create-a-document.mdx` (another writer's page) compiles with one inline-math node under remark-math, which usually means an unescaped pair of `$` signs; check it renders as intended.

- `/command-center/approvals-and-compliance` — No UI to undo a contact-change rejection or a compliance waiver; the playbook treats both as DESTRUCTIVE. Server-side role permissions for these actions are unverified.

- `/command-center/work-queue-and-management` — `/work-queue` and `/management` are in no sidebar or tab bar; only direct URLs, Management links and readiness-checklist buttons reach them.
- `/operations/inbox` — Help guide `service-desk-inbox` presents **Mine / Everyone** as available to everyone; code renders the switch and **Person** picker only for Principals (`page.tsx:213`, `queue-rail.tsx:156`).

Guide says admins can unmerge; code allows only Principal (`operationsAllCases`) or the assignee. An Operator who merges a case they do not own cannot reverse it.

- `/operations/case` — Help guide `ops-reply` says to **Stage for reply** an Ariya document but omits that it must first be **Link**ed in the Documents tab; `?stage=` also only works for already-linked documents.

- `/operations/settings` — **Save & scan** and learned-rule **Pause** / **Reactivate** are shown to every role while domain lists are read-only for non-admins; server permission for Operators is unverified.
- `/operations/settings` — Removing a domain/keyword chip is immediate with no confirmation.
- `/operations/settings` — Help modal step 5 says Ariya "will immediately begin scanning your last 30 days"; the callback page only says "Ariya will now monitor your inbox." Whether a scan starts automatically is unverified.

### Clients, people and contacts

- **Dead API route:** `/contacts` and `/contacts/{id}` call `/api/contacts`, `/api/contacts/unlinked`, `/api/contacts/{id}`, `/api/contacts/change-requests` and `/api/contacts/unlinked/export`, but `packages/transport-api/src/routes/contacts.ts` is not mounted in `server.ts` (only `/contact-change-requests` at :216). Lists show "No contacts yet." (errors swallowed), detail shows "Contact not found", change-request submits and Export CSV fail. Page: /clients/people-and-contacts
- **UI/API mismatch (Operator):** `/clients` row **HR Advisor** select is not role-gated; Operator and Member get the 403 text in a red box. `packages/web/src/app/(dashboard)/clients/page.tsx:1081`. Page: /clients/clients-list
- **UI/API mismatch + invisible errors:** Profile Workspace **Save** is not role-gated (403 for Operator/Member), and all its errors (403, "Add a name or email to save this contact.") render in the portfolio card that is hidden on `?view=profile-workspace`. A failed save just leaves the row in place. Page: /clients/clients-list
- **Inconsistent approval path:** Profile Workspace contact save creates contacts directly (`POST /api/clients/{slug}/contacts`), while the client People & Roles tab routes every contact change through approval. Page: /clients/clients-list
- **No error state:** `/clients` has no catch on `api.clients.list()`; on failure the table shows skeleton rows forever (`clients/page.tsx:548`). Page: /clients/clients-list
- **Misleading empty state:** "No customers yet. Run a read-only HubSpot import or add a customer manually." also shows when search or filters match nothing. Page: /clients/clients-list
- **Dead param:** Profile Gaps badge links to `/clients/{slug}?action=complete-profile#client-profile-fields`; nothing handles `action` or that anchor, and the saved-tab redirect may drop it. Page: /clients/clients-list
- **Saved-tab redirect from list links:** client links from an unfiltered `/clients` omit `?tab=`, so the client page redirects to the user's last-used tab instead of Overview. Page: /clients/client-profile
- **No stage editor:** inline name/industry/stage edit exists in `clients/page.tsx` but its column is not rendered (:1413). The `/clients/new` partial-success toast "Client created, but the stage could not be saved. Set it from the client list." points to a control that does not exist. Page: /clients/new-client
- **Help drift (clients-list):** guide says HubSpot companies need lifecycle "Customer"; code checks `ariyaClientStatus === 'active'` (`routes/clients.ts:433`). Page: /clients/clients-list
- **UI/API mismatch (Operator):** External Documents tab has no view-only wrapper; upload, re-read, date correction and remove are enabled for Operator/Member but the API (`/api/clients/{slug}/external-documents`, clientsPackets edit) returns 403. Page: /clients/client-tabs-work
- **UI/API mismatch (Operator):** Compliance tab is editable for Operator (clientHrRecords) but **Run research** / **Start research** posts to `/api/clients/{slug}/research/runs` (clientsPackets) and returns 403. Page: /clients/client-tabs-people-hr
