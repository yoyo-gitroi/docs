<Info>
**Use with:** the Document Assistant chat (`/documents/chat/{sessionId}`), reached from sidebar **Documents** → send a request · **Roles:** Principal ✓ Operator ✓ · **Verify in:** sidebar **Documents** → **Templates**, because tenants can rename, add or deactivate templates.
</Info>

Use this page to turn a user's words into a template title and a complete request. Each template links to its catalog entry, which lists every field and a full good request. The click path for sending the request is [Create a document](/documents/create-a-document).

<Note>
Unverified: the word-search results on this page (ties, sort order, "matches nothing") come from an offline simulation of the assistant's template search against the seeded catalog, using the short phrase only. A real sentence has more words and can rank differently, and the assistant makes the final pick. Treat them as warnings, not guarantees.
</Note>

## Rules that make routing reliable

1. **Name the client exactly.** The assistant binds a client only on one confident match, and drafts nothing until it has one.
2. **Say the full template title** as shown in **Documents** → **Templates**: "non-disclosure agreement", "incident report", "Corrective Action Warning". Platform templates have no aliases, words under 3 characters are ignored, and abbreviations (NDA, PIP, DE 48, QBR) are unreliable.
3. **When two templates share a title or a word, add the slug** in the request, for example "Service Agreement (service-agreement)".
4. **Expect a confirmation question** whenever several templates share a word: warnings, proposals, service agreements, handbook variants, incident reports, workers' comp. Answer it with the title.
5. **Put every fact in the first request.** The assistant asks only for true blockers (for example the employee name on an offer letter) and flags the rest as blank gaps. It never fills in values you did not give.
6. **Attach source files** (notes, spreadsheets, an existing handbook) instead of pasting long data. Attached files count as a valid source for field values.
7. **Create the three PDF forms from Documents → Templates**, not the assistant.
8. **Do not hand-pick** `elevated-hr-roadmap`, `elevated-hr-assessment`, `elevated-hr-roadmap-progress`, `implementation-billing-memo` or `billing-memo`. Their modules create them.

## Routing cheat-sheet

Read "Put in the request" as the minimum facts that avoid a follow-up question or a blank gap. The linked catalog entry has the complete list.

## Phrases with no template

No seeded template exists for these. Tell the user, and ask which existing template to use or whether a Principal should create one in **Settings** → **Templates**.

| User says | What exists instead | Watch out |
|---|---|---|
| "PIP"; "performance improvement plan" | Operations case and client-workspace rules route to [Written Warning](/documents/catalog/business#written-warning) `written-warning`. [Performance Review](/documents/catalog/business#performance-review) `performance-review` has a **PIP / Performance Improvement Plan** period option. | "PIP" matches nothing in the word search; "performance improvement plan" surfaces Performance Review and 30-60-90 day plan. Whether your tenant has its own PIP template is unverified; check **Documents** → **Templates**. |
| "separation agreement" | [Severance summary](/documents/catalog/business#severance-summary) `severance-summary` (cover summary) or [Termination Letter](/documents/catalog/business#termination-letter) `termination-letter` | Client-workspace rules map "separation" to Termination Letter. Unverified whether a tenant template exists. Ask. |
| "handbook addendum" | None seeded | Exists only as an HR Roadmap linked-document value; a tenant may have authored one (unverified). Ask. |
| "ERISA plan document" | None | Client-workspace suggestions report "Missing template: ERISA plan document". |

## Other places that suggest templates

- **Operations cases** show "SUGGESTED TEMPLATES" from keyword rules: warning or PIP language suggests Written Warning; investigation language suggests HR Incident Report ("Incident / Investigation Summary"); compliance language (including "handbook") suggests HR Compliance Checklist; onboarding or hiring words suggest New Hire Packet; job-description words suggest Job Description; other cases fall back to HR Roadmap.
- **Client workspace document opportunities** suggest templates from client evidence. They can still propose the retired `incident-report-rdk`, and they map "status report" to Quarterly Business Review and "90 days" to HR Roadmap.
- **HR Roadmap tasks** have a "linked doc type" with a **Draft** action. Several values (`pip`, `separation-agreement`, `handbook-addendum`, `policy`, `safety-manual`, `onboarding-checklist`, `offboarding-checklist`, `idp`, `training-plan`, `verbal-warning`, `audit-guide`, `compliance-audit`, `hr-proposal`) are not template slugs, so the draft lands on the nearest template or on HR Roadmap.
