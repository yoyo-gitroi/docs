**URL:** `/admin` and `/admin/tenants`, `/admin/tenants/{id}`, `/admin/skills`, `/admin/skills/new`, `/admin/skills/{id}`, `/admin/governance`, `/admin/profiles`, `/admin/team`, `/admin/ariya-memory`, `/admin/platform-memory`, `/admin/platform-settings`, `/admin/integrations`, `/style-guide` · **Reach:** sidebar **Platform Admin** (under **Admin & Setup**), then the Platform Admin tab bar · **Roles:** Principal ✓ Operator ✗ · **Ready when:** the page h1 is visible and `Loading…` is gone.
</Info>

Platform-wide controls. Changes here can affect every tenant.

<Note>**Principal of tenant `ariya` or `pilot` only.** Every `/admin/*` data call is refused for everyone else with `Principal access required`. A Principal in a customer tenant sees the menus but every page fails. **Operator:** no menu entry. Typing an admin URL shows either a blocked card (`Reply Voice, governance, skills and memory is not available on the Operator profile.` on Master Skills and Governance; `Only a Principal can open Profiles.` on Profiles) or a page that loads with `Principal access required` errors. `/style-guide` has no gate. Trusted Sources is on [Data and sources](/intelligence/data-and-sources#find-a-trusted-source).</Note>

## Page map

## Recipes

### Check the admin endpoint
**Risk:** `READ` · **Roles:** Principal
**Inputs from Clarwiz:** none.
**Preconditions:** none.

1. Open `/admin`.
   - Wait for: h1 **Platform Admin** and the `Admin endpoint` tile to leave `Checking`.
2. Read `Admin endpoint`: `Verified` means admin calls work. `Error` shows the API error in its detail line.
3. In `Tenant Snapshot`, a warning `You are signed in as {role}, not principal. Platform admin requests will be rejected.` means you are on the wrong account.

**Done when:** the tile reads `Verified`, or you have reported the error.

### List tenants
**Risk:** `READ` · **Roles:** Principal
**Inputs from Clarwiz:** none.
**Preconditions:** none.

1. Open `/admin/tenants` (tab **Tenants**).
   - Wait for: the table (`Loading…` gone).
2. Read `Tenant`, `ID`, `Members` (`{active}` or `{active} / {total}`), `Created`.

**Done when:** the table or `No tenants found.` is visible. Error: `Error: {error}`.

### Inspect a tenant
**Risk:** `READ` · **Roles:** Principal
**Inputs from Clarwiz:** tenant name or ID.
**Preconditions:** none.

1. Open `/admin/tenants/{tenantId}`, or click the tenant name in `/admin/tenants`.
   - Wait for: h1 `{tenant name}` and stat cards `Clients`, `Requests`, `Documents`.
2. Read `Members ({n})` and the `Memory` section.
3. In the memory inspector, filter with category buttons **All**, `Facts ({n})`, `Heuristics ({n})`, `Preferences ({n})`, `Corrections ({n})` and status buttons **live**, **archived**, **all**.

**Done when:** the memory table (`Cat`, `Key`, `Content`, `Status`, `Source`, `Updated`, `Actions`) or `No memory rows match the current filter.` is visible. Loading `Loading memory…`; errors `Error: {error}`.

### Edit a tenant memory row
**Risk:** `WRITE` · **Roles:** Principal
**Inputs from Clarwiz:** tenant, memory key, new content or status.
**Preconditions:** tenant detail open.

1. Find the row by `Key`.
2. Click the pencil icon button (title "Edit"; visual: `Actions` column).
   - Wait for: content becomes a text area and status becomes a native select (`active`, `core`, `proposed`, `superseded`, `archived`).
3. Change the content or status.
4. Click the save icon button (title "Save"). The X icon (title "Cancel") discards.

**Done when:** toast `{key} updated` (or `No changes`). Failure: `Save failed: {error}`.

### Archive or restore a tenant memory row
**Risk:** `DESTRUCTIVE` (archive, soft) / `WRITE` (restore) · **Roles:** Principal
**Inputs from Clarwiz:** tenant, memory key; approval for archive.
**Preconditions:** tenant detail open.

<Warning>**Approval required (DESTRUCTIVE).** Stop here and get approval before clicking **Archive**. It acts at once with no confirm.</Warning>

1. On a non-archived row click the archive icon button (title "Archive"). On an archived row, the restore icon button (title "Restore") brings it back.

**Done when:** toast `{key} archived` or `{key} restored`. Failure: `Archive failed: {error}` or `Restore failed: {error}`.

### View another tenant
**Risk:** `READ` (writes made while switched land in that tenant) · **Roles:** Principal of `ariya` or `pilot`
**Inputs from Clarwiz:** tenant ID.
**Preconditions:** none. There is no tenant switcher in the UI.

1. Take the URL of the page you need and append `?tenant_id={tenantId}` (use `&tenant_id=` if the URL already has a query). Example: `/clients?tenant_id={tenantId}`.
2. Open it.
   - Wait for: the page to load. Every data call from this page now uses that tenant.
3. Before every further step, check the URL still has `tenant_id`. Sidebar and tab links drop it, so after any link click you are back in your own tenant. Re-append it on each page.

**Done when:** the page shows the other tenant's data.

| If you see | Why | Do this |
|---|---|---|
| `Tenant access denied` | You are not a Principal of an internal tenant | Remove the parameter. |
| Your own tenant's data after a click | The link dropped `tenant_id` | Re-append the parameter. |
| `/usage` or Memory approvals ignore the switch | Those pages hard-code tenant `ariya` | Do not rely on switching there. |

<Warning>Anything you create or change while switched is written to that tenant. Confirm the tenant ID with Clarwiz before any WRITE. Proxy login is not offered while the URL carries `tenant_id`.</Warning>

### Create a master skill
**Risk:** `WRITE` (an active skill applies to every tenant's agent) · **Roles:** Principal
**Inputs from Clarwiz:** name, description, status, triggers, example inputs, when to use, workflow; or a Markdown manifest.
**Preconditions:** none.

1. Open `/admin/skills/new` (or **New master skill** on `/admin/skills`).
   - Wait for: h1 **New master skill** and card `Import skill manifest`.
2. Optional, to import a manifest:
   1. Paste the manifest into the manifest text area (7 rows; visual: inside `Import skill manifest`), or click **Upload .md**, or click a sample (**Draft checklist**, **Approval request**).
   2. Click **Parse into form** (disabled while empty).
   3. Read the result: red `Fix before import`, amber `Review before saving`, green `Import preview` (`Risk`, `Tools`, `Required inputs`, `Outputs`).
   4. On success, toast `Manifest imported as draft`; the form below is filled and **Status** is draft. Failure: toast `Import failed: {error}`.
3. Fill the form. Labels sit above fields but are not linked to them; find fields by label text or placeholder:
   - **Name** (placeholder "check-compliance"): lowercase kebab-case; cannot change after creation.
   - **Description** (placeholder starts "Evaluate compliance posture"): one line.
   - **Status** (native select): `active — applied to agent runs` (default), `draft — saved but not applied`, `archived — hidden, not applied`. Choose draft unless Clarwiz says active.
   - **Triggers**: one per line (counter `{n} trigger(s)`).
   - **Example inputs**: one per line.
   - **When to use** (required).
   - **Workflow** (required; counter `{n} chars`).
4. Click **Create skill** (submit; visual: bottom of the form).
   - Wait for: `Saving…`.

**Done when:** toast `Skill saved` and the URL becomes `/admin/skills/{id}`.

| If you see | Why | Do this |
|---|---|---|
| Browser bubble on a required field | Field empty | Fill it. |
| Toast `Save failed: {error}` and red card `Error: {error}` | Server refused (for example a duplicate name) | Fix and retry. |

### Archive or restore a master skill
**Risk:** `DESTRUCTIVE` (archive, soft) / `WRITE` (restore) · **Roles:** Principal
**Inputs from Clarwiz:** skill name; approval for archive.
**Preconditions:** `/admin/skills` open.

<Warning>**Approval required (DESTRUCTIVE).** Stop here and get approval before clicking **Archive**. The skill stops applying to agent runs in every tenant.</Warning>

1. On the row, click **Archive** (text button, title "Archive").
   - Wait for: a **native browser confirm** `Archive this skill? It will stop being applied to agent runs.` Accept it.
2. To undo, click **Restore** on an archived row (no confirm).

**Done when:** the list reloads and the `Status` cell changes. There is no toast and failures are not shown; reload and check the status.

### Assign a profile to a person
**Risk:** `WRITE` (changes what the person can do; saves instantly) · **Roles:** Principal
**Inputs from Clarwiz:** person, new profile.
**Preconditions:** not in proxy login.

1. Open `/admin/profiles` (tab **Profiles**, or the **Profile** link on a `/admin/team` row).
   - Wait for: h1 **Profiles** and card `People ({n})`.
2. Find the person's row (name and email).

<Warning>Picking an option saves immediately, with no confirm and no undo button. Confirm the person and the profile with Clarwiz before you open the dropdown.</Warning>

3. Click the row's **Profile** dropdown and click `Principal`, `Admin`, `Operator` or `Member` (`Principal` only where assignable; the dropdown is disabled while saving).

**Done when:** toast `Profile set to {Profile}`. The change applies on the person's next request. Failure: red toast with server text; during proxy login `Not available during proxy login: managing Profiles.`

### Invite a platform team member
**Risk:** `EXTERNAL` `WRITE` (sends an invitation email) · **Roles:** Principal
**Inputs from Clarwiz:** email, role; approval.
**Preconditions:** none.

1. Open `/admin/team` (tab **Platform Team**).
   - Wait for: h1 **Ariya Team** and card `Invite a member`.
2. Click the email input (no label, type email, placeholder "email@example.com") and type the email.
3. Pick the role in the native select next to it: `Admin` (default), `Operator`, `Member` (`Principal` for Principals).

<Warning>**Approval required (EXTERNAL).** Stop here and get approval before clicking **Send invite**. It emails the person.</Warning>

4. Click **Send invite** (disabled while email is empty).
   - Wait for: `Sending…`.

**Done when:** green text `Invitation sent to {email}` under the form and a row in `Pending invitations ({n})`. Failure: red text with the server error.

### Resend or revoke an invitation
**Risk:** `EXTERNAL` (resend) / `DESTRUCTIVE` (revoke) · **Roles:** Principal
**Inputs from Clarwiz:** invitation email; approval.
**Preconditions:** `Pending invitations` table visible.

<Warning>**Approval required (EXTERNAL or DESTRUCTIVE).** Stop here and get approval before clicking **Resend** (sends email) or **Revoke** (invalidates the invitation).</Warning>

1. Resend: click **Resend** on the row. A **native alert** `Invitation resent.` appears; accept it.
2. Revoke: click **Revoke** (disabled when already revoked). Accept the **native confirm** `Revoke this invitation?`

**Done when:** the alert was shown (resend) or the row status changes (revoke). Errors arrive as native alerts.

**Inputs from Clarwiz:** member email; approval for deactivate.
**Preconditions:** `Members ({n})` table visible.

<Warning>**Approval required (DESTRUCTIVE).** Stop here and get approval before clicking **Deactivate**. The person loses access.</Warning>

1. Click **Deactivate** (or **Reactivate**) on the member row.
2. Accept the **native confirm** `Deactivate this member?` (or `Reactivate this member?`).

**Done when:** the row shows or loses `(inactive)`. Errors arrive as native alerts.

### Change the platform sign-in policy
**Risk:** `DESTRUCTIVE` (can lock out password sign-in for everyone, including the agent) · **Roles:** Principal
**Inputs from Clarwiz:** allowed domains and flags; approval.
**Preconditions:** `/admin/team` open.

1. In `Invite a member`, find **Allowed email domains** (input, id "platformAllowedDomains", placeholder "ariyahr.com"; comma or space separated).
2. Set the native checkboxes **Google SSO ready**, **Require SSO**, **Require MFA**, **Passkeys ready**.

<Warning>**Approval required (DESTRUCTIVE).** Stop here and get approval before clicking **Save policy**. **Require SSO** or **Require MFA** blocks email-and-password sign-in, which the agent depends on.</Warning>

3. Click **Save policy**.

**Done when:** no error alert appears (there is no success message). Reload and re-read the checkboxes to confirm.

### Query Ariya company memory
**Risk:** `AI` `READ` · **Roles:** Principal
**Inputs from Clarwiz:** the question.
**Preconditions:** `API enabled` gate is on.

1. Open `/admin/ariya-memory` (tab **Ariya Memory**).
   - Wait for: `Backend Release Gates` tiles. An amber alert starting `Ariya company memory is visible here for admin planning, but query and audit calls are disabled` means queries cannot run; stop and report.
2. Click the query text area (placeholder "Ask a source-backed Ariya company-memory question...") and type the question. Or click a prompt button (**What is blocking the Ariya memory MVP?**, **What did we decide about CentCom and Ariya memory?**, **What source supports the Ariya memory source inventory gate?**), which runs at once.
3. Click **Search memory** (disabled unless enabled and non-empty).
   - Wait for: `Searching` to finish.

**Done when:** the `Answer` card shows badges, text, `Guardrails` and `Citations` (`Updated {date}`, **Open source** in a new tab) or `No citations returned.`

| If you see | Why | Do this |
|---|---|---|
| `Enter a query before searching Ariya memory.` | Empty query | Type a question. |
| `Query failed: {error}` or toast `Ariya memory query failed: {error}` | Server error | Report. |
| `Health check failed: {error}` | Health load failed | Click **Refresh**; report. |

### Promote a tenant memory to platform
**Risk:** `AI` `WRITE` (anonymizes with an LLM, then shares across tenants) · **Roles:** Principal
**Inputs from Clarwiz:** tenant ID, source type, source memory UUID, optional industry and jurisdiction.
**Preconditions:** none.

1. On `/admin/platform-memory`, click **Promote from tenant**.
   - Wait for: card `Promote a tenant memory to platform` above the table.
2. Fill fields (placeholders only, no labels): "tenantId"; the source dropdown `client_memory` or `tenant_memory`; "sourceId (UUID)"; "industry (optional)"; "jurisdiction (optional)".
3. Leave **Skip anonymizer (already curated)** unticked unless Clarwiz says otherwise.
4. Click **Promote** (needs tenantId and sourceId).
   - Wait for: `Promoting…`.

**Done when:** toast `Promoted` and the row appears.

| If you see | Why | Do this |
|---|---|---|
| Warning toast `Promotion rejected: {reason}` | The anonymizer or leak check refused it | Report the reason; do not skip the anonymizer to force it. |
| `Promotion failed` or `{error}` | Server error | Report. |

### Start a proxy login
**Risk:** `WRITE` (you act as another person; every change is recorded as proxied by you) · **Roles:** Principal only
**Inputs from Clarwiz:** the person to act as; explicit instruction to use proxy login.
**Preconditions:** the URL has no `tenant_id`; the target is active, not you and not a Principal.

1. Open `/settings/team`.
2. Find the person's row and click the icon button with aria-label `Proxy login as {name}`.
   - Wait for: a dialog titled `Proxy login as {name}?` with the description `You will use the whole app as this person for up to 1 hour. You cannot send email from their Gmail or change their password, sign-in or MFA. Everything you change is recorded as proxied by you.`
3. Click **Start proxy login** (or **Cancel**).

The same flow is described with the Team Access page in [Proxy login as a user](/settings/general-and-team#proxy-login-as-a-user).

**Done when:** the violet `PROXY LOGIN` strip shows `Viewing as {name} ({Profile}) · {email}`. To end it see [Recognise and exit a proxy login](/start/login-and-session#recognise-and-exit-a-proxy-login).

## Waits and signals
- Most admin pages show `Loading…` then a table. Errors appear as `Error: {error}` cards or toasts.
- `/admin/team` reports success as green text, and errors and resends as native browser alerts.
- `/admin/skills` archive and restore give no toast; the list reloads.
- Promotion can take several seconds (LLM anonymizer).

## Gotchas
- Native browser dialogs on `/admin/skills` (archive), `/admin/team` (deactivate, reactivate, revoke, resend alert, error alerts) and `/admin/platform-settings` (remove). Accept or dismiss them through your automation.
- Profiles dropdown, memory archive buttons and platform memory archive save with no confirm.
- `/admin/skills/{id}` is read-only and tells you to edit source code; you cannot edit an existing master skill in the UI.
- Governance is read-only, although `/admin` cards say "edited with review gates" and "Review before save".
- The tab says **Platform Team**; the page h1 says **Ariya Team**.
- Platform Memory and the skill form use placeholders or unlinked labels; locate fields by placeholder or nearby label text.
- Master skill archive and restore failures are not shown at all; always reload and verify.
- Tenant switching is lost on every link click.
- These pages have no in-app guide of their own; **?** opens `How Ariya fits together`.
